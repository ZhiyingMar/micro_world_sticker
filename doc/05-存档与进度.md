# 05 · 存档与进度

所有进度存在浏览器的 `localStorage` 里，键是 `micro_world_save_v1`，内容是一个 JSON 对象。读写都在 `src/state.js`。

## 存档长什么样

一个玩到一半的存档大概是这样（注释是说明，实际存档里没有）：

```js
{
  current: 'city',                      // 上次在哪个世界，下次打开回到这里
  magnets: ['forest', 'pixel', 'city'], // 已获得的冰箱贴 = 已解锁的世界（小屋是家，不在里面）
  newMagnet: null,                      // 刚获得、还没进去过的冰箱贴（冰箱上显示 NEW!）
  found: {                              // 每个世界找到了哪些物品
    home: ['mushroom', 'book', 'star'],
    forest: ['coin', 'heart', 'cartridge'],
    pixel: ['moon', 'taxi', 'sax'],
    city: ['teapot'],
  },
  repaired: { city: ['moon'] },         // 破败世界里放回去了哪些东西
  flags: {                              // 破败世界里的其他进度
    city: ['seen:moon', 'seen:taxi', 'coin', 'coffee'],
  },
  materials: { plastic: 5, glass: 1 },  // 材料背包，各世界共用
  decor: {                              // 小屋装修
    wallpaper: 'mint-stripes',          //   现在用的壁纸（没有就是默认那款）
    floor: 'oak',
    owned: ['mint-stripes'],            //   工作台上做过的
  },
  greeted: { home: true, forest: true, 'city:broken': true }, // 谁已经主动打过招呼
  seenIntro: true,                      // 看过开场说明
  rotateHinted: true,                   // 提示过"手机横过来玩"
  muted: false,                         // 静音
}
```

## state.js 的接口

| 函数 | 说明 |
|---|---|
| `state` | 就是上面那个对象。直接读写字段，改完调 `save()` |
| `save()` | 写进 localStorage。写不进去（隐私模式）就算了，不影响玩 |
| `foundIn(sceneId)` | 某个世界找到的物品数组（没有就建一个空的），直接 `push` |
| `repairedIn(sceneId)` | 某个世界修好的修复点数组 |
| `flagsIn(sceneId)` | 某个世界的其他标记数组 |
| `materialCount(id)` / `addMaterial(id, n)` / `canAfford(cost)` / `spendMaterials(cost)` | 材料背包；扣不够会直接抛错，不会扣成负数 |
| `resetSave()` | 删存档（结局里"从头再玩一次"） |
| `useMemorySave(preset)` | 换成一份只在内存里的进度，之后 `save()` 不再写盘。宣传片模式用，录完玩家的存档一点不变 |

`load()` 读档时用 `{ ...fresh(), ...存档 }` 合并：**新加的字段老存档里没有，会自动用默认值补上**。`repaired`、`flags`、`materials`、`decor` 这些后来加的字段，在用到时也会按需建出来。

## 进度标记一览（`flags`）

目前只有霓虹夜都用：

| 标记 | 意思 |
|---|---|
| `seen:moon` `seen:taxi` `seen:sax` | 发现过这个修复点（走近过），下次进来虚影直接显示 |
| `coin` | 捡到硬币 |
| `coffee` | 在售货机买了咖啡 |
| `driver` | 叫醒了司机老周 |
| `tetris` | 通关过大楼俄罗斯方块（居民台词会提到） |

## 老存档兼容

`AGENTS.md` 的规矩："改进度、修复点、物品时，老存档必须还能用。"现在代码里处理了这几种情况：

1. **世界在"破败版"之前就通关了**：`World` 构造时，如果这个世界的物品都找齐了（`complete`），而它有 `repairs`，就把所有修复点直接记成修好。夜都的 `loadProgress()` 再把 `coin`、`coffee`、`driver` 都补上。玩家回来看到的是已经亮灯的夜都。
2. **最早那版夜都原型没有"叫醒司机"这一步**：那时出租车放回去车就开了。老存档里出租车修好了，却没有 `seen:taxi`（新版本一定是先发现、再修）。`loadProgress()` 认出这种情况（`legacyTaxi`），把中间步骤补成做完，不然车永远不动。
3. **装修款式从目录里删了**：`currentDecor()` 退回默认款，`console.warn` 一声，不让小屋缺墙。
4. **存档里的当前世界打不开**（结局、施工中）：启动时退回小屋。

## 读档时的"瞬间恢复"

进一个世界时，`World` 会对存档里每个修好的修复点调 `repair(id, instant = true)`。所有 `fn(instant)` 都要处理好 `instant`：

- `instant = true`：直接变成修好的样子，不播音效、不放粒子、不弹提示、不触发"全部修好"的庆祝。
- `instant = false`：玩家刚放回去，播完整的动画。

比如夜都的出租车：`instant` 时车直接摆在正常行驶的位置；不然先停着，1.1 秒后按喇叭，再一辆辆开起来。

## 测试时的注意

在浏览器里测试时如果改了存档（比如用 `__mw.state` 直接改字段、或者玩了一段），测完要恢复。可以先在控制台备份：

```js
copy(localStorage.getItem('micro_world_save_v1'))   // 复制到剪贴板
// …测完…
localStorage.setItem('micro_world_save_v1', '粘贴回来的内容')
```

也可以用宣传片模式那种内存存档的思路，不碰真存档。
