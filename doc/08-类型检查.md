# 08 · 类型检查（JSDoc + @ts-check）

代码还是 `.js`，Vite 照常跑；只是多了一个 `npm run typecheck`，用 TypeScript 的检查器读 JSDoc 里写的类型，把"拼错字段名、传错参数、少处理一种情况"在打开浏览器之前就找出来。现在 `src/main.js` 是第一个接上的文件，可以照着它改别的。

## 怎么跑

```bash
npm run typecheck
```

没有输出就是零报错。VS Code 会直接读 `jsconfig.json`，打开 `main.js` 时错误会用红波浪线标出来，鼠标放上去能看到类型。

## 涉及的文件

| 文件 | 作用 |
|---|---|
| `jsconfig.json` | 检查的设置。`checkJs: false`：**只查第一行写了 `// @ts-check` 的文件**，可以一个个慢慢加 |
| `src/types.js` | 大家共用的数据形状，全是 JSDoc `@typedef`：`SceneDef`（世界定义）、`SceneCamera`、`ItemDef`、`RepairDef`、`MaterialDef`、`GameDef`… 运行时不做任何事 |
| `src/globals.d.ts` | 标准类型里没有、要补上的全局东西：Safari 带 webkit 前缀的全屏接口、调试用的 `window.__mw` |
| `src/scenes/index.js` | 给 `SCENES` 标上 `Record<string, SceneDef>`，于是 `main.js` 里 `SCENES[id]` 拿到的就有类型了 |

依赖：`typescript`（只用来检查）、`@types/three`（three.js 的类型，版本跟 three 对上）。

## 给一个文件接上类型：main.js 里用到的 5 种改法

`main.js` 开了 `// @ts-check` 后报了 14 处，正好是 5 类，基本覆盖了以后会遇到的情况。

### 1. `@param {object}` 太笼统 → 换成真正的类型

```js
// ✗ object 上什么字段都没有，def.camera 会报错
 * @param {object} def 世界的定义
// ✓ 先在文件顶上起个短名字，再用它
/** @typedef {import('./types.js').SceneDef} SceneDef */
 * @param {SceneDef} def 世界的定义
```

好处马上就有：把 `c.min` 拼成 `c.minn`，检查器会说 *Property 'minn' does not exist on type 'SceneCamera'. Did you mean 'min'?*——以前这种错不报，`undefined || 2.5` 悄悄退回默认值，很难发现。

### 2. 数组要当成固定几个数 → 写成元组

`sun.position.set(...sp)` 报错，因为检查器只知道 `sp` 是"一串数字"，不知道正好 3 个。在类型里写成 `[number, number, number]`（见 `types.js` 的 `SceneLights`）就好了。

### 3. 类型报错指出了更准确的写法

```js
// ✗ event.target 可能是任何东西（甚至不是元素），没有 .id
if (event.target.id === 'workbench') { … }
// ✓ target 是真正点到的元素，currentTarget 是挂监听的面板：一样 = 点在空白处
if (event.target === event.currentTarget) { … }
```

意思和原来一样，但不再依赖"面板的 id 恰好是这个字符串"。

### 4. 检查器知道的比你少 → 用 JSDoc 强制转换

```js
// querySelector 只知道返回 Element（没有 .style）
const stick = /** @type {HTMLElement} */ (joy.querySelector('.stick'));
```

注意**括号必须有**，`/** @type {…} */ (表达式)` 才是转换。只在你确实比检查器知道得多时用（这里 HTML 里那个就是 div），别拿它压掉真正的错。

### 5. 全局的东西 → 在 `globals.d.ts` 里补声明

`document.webkitExitFullscreen`、`window.__mw` 这种标准类型里没有的，在 `globals.d.ts` 里给 `Document` / `HTMLElement` / `Window` 补字段。这是项目里唯一的 `.d.ts`，只放这类全局补丁。

## 下一步可以接哪些文件

建议顺序（越往前越值）：

1. `src/state.js`：存档形状写成一个 `SaveState` typedef，老存档兼容出错最疼。
2. `src/world.js`：`interact` / `hideout` / `repairSpot` / `game` 的参数写成 typedef，世界文件调用时就能检查。
3. `src/scenes/index.js`：开了以后会发现 `finale`（全家福）不满足 `SceneDef`——它没有 `build`、`lights`。到时候要把"冰箱贴"和"世界"拆成两种类型（`types.js` 的 `SceneDef` 注释里记着）。
4. `src/scenes/city/`：模块之间互相传的小对象（`power`、`traffic`、`block`）。

每接一个：第一行加 `// @ts-check` → `npm run typecheck` → 按上面 5 种改法修到零报错 → 浏览器里走一遍 → 提交。

## 以后打开"可能是 null"的检查

`jsconfig.json` 里现在 `strictNullChecks: false`。打开它，`main.js` 会报 250 多处，几乎都来自同一个原因：

```js
let world = null;   // 检查器认为 world 的类型就是 null
…
world = new World(def, env);   // 报错：World 不能赋给 null
world.update(…);               // 报错：world 可能是 null
```

改法分两步：

```js
// 1. 声明时写清楚它会是什么
/** @type {World | null} */
let world = null;

// 2. 用到的地方让检查器知道此时一定有值。
//    能确定"走到这里世界肯定加载好了"的，在函数开头判断一次；
//    按 AGENTS.md，不该发生的情况要报错，不要悄悄 return
function refreshGoal() {
  if (!world) {
    throw new Error('refreshGoal：世界还没加载');
  }
  // 下面 world 就是 World 了
}
```

`player`、`overview`、`game`、`focus`、`down` 这些一开始是 `null` 的变量同理；`document.getElementById(...)` 返回的元素也可能是 `null`，可以写个小帮手（找不到就报错的 `$('#id')`）统一处理。这一步改动面大，建议等几个核心文件都接上类型以后再做。

## 类型管不到的

类型只查"形状"对不对。画面对不对、人会不会卡在崖边、车让不让人、镜头取景这些，还是得在浏览器里看。比如这次检查时顺便发现：页面在 0×0 大小时加载（浏览器面板还没显示出来），镜头位置会变成 `NaN`，之后窗口变大也恢复不了——`NaN` 也是 `number`，类型检查不会报。
